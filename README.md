# aad-pricer

A C++23 Monte Carlo pricer for path-dependent options (Asians, barriers, digitals), with its own tape-based adjoint algorithmic differentiation (AAD): one backward pass gives the price and every first-order Greek. It is measured against published targets, each with its source in [BENCHMARKS.md](BENCHMARKS.md), and against bump-and-revalue and a hand-written adjoint on the same random numbers.

The emphasis is on checking the numbers. Every comparison against a reference value was registered, with its tolerance, before the run that judged it, and a failed comparison stays failed. A fault-injection runner plants one bug at a time to prove each check can fail. The results tables here are generated from stamped measurement files, and the headline below includes the targets it missed.

It also fits an SVI volatility surface to one trade date of TAIFEX index-option settlement prices and prices off it, and has a QuantLib comparison bench. Those parts are built and tested, and their measured runs are still to come.

## What is here

- A platform layer for arm64 and x86-64: CPU information, timers, pinning, performance counters, floating-point state.
- Google Benchmark and HdrHistogram harness code, and a results-file writer that stamps each run with its host, compiler and flags.
- Own `exp`, `log` and AS241 inverse normal in `src/math/`, so libm differences do not reach results.
- The production scalar pricer in `src/pricer/`: arithmetic and geometric Asian, European, digitals, and barriers with a Brownian-bridge weight, one-step survival, a hard indicator or smoothing, on Philox draws keyed on path and step, multi-threaded with a fixed block order.
- The tape in `src/ad/`: struct of arrays, one statement per operation, one tape per worker thread, with no allocation after warm-up. A hand-written adjoint of the GBM Asian is the baseline it is measured against. Second-order Greeks by forward over reverse, and SIMD lanes with a vector tape.
- Bump and revalue on common random numbers, with step sizes from a committed h study, and an AAD benchmark that checks every gradient inside the run before timing it.
- Closed-form and finite-difference oracles, with the tolerance rule implemented once and every comparison fixed in `references/comparison_plan.csv`. Measured run 1 ran the comparisons runnable in Phase 2 on the reference kernels (`references/measured_results.csv`). Measured run 2 ran all of them on the production pricer and tape (`references/measured_results_run2.csv`); its two failures are in the headline and in `docs/NOTES.md`, "Stage 8b: measured run 2". Run 1 is kept beside run 2, unchanged.
- A raw SVI fit to the TAIFEX settlements, an arbitrage-free eSSVI surface beside it, local volatility off the surface, and sensitivities of prices to the calibration settlements through the fit. The surface reaches 33 days only. Stage 7b's registered bump-and-recalibrate check fails on 20 of its 1,080 price comparisons, all on the barriers, in an iteration run that is not a result (`docs/NOTES.md`, "Stage 7b results").
- A Metal GPU backend in `src/metal/`, built on Apple when Metal is found: float32 prices only, for the GBM arithmetic Asian and the one-step-survival barriers. AAD does not run on the GPU. The GPU computes prices and nothing else, and every Greek comes from the CPU, in double precision, by the tape or by bump and revalue. Its kernel source, `src/f32/float_kernels.hpp`, also runs on the CPU as a float32 line, and both are compared with the double pricer on the same truncated uniforms.
- A QuantLib comparison bench in `bench/quantlib/`, behind `AAD_PRICER_BUILD_QUANTLIB_COMPARE`.
- cp950 and TAIFEX file readers, and libFuzzer targets on every parser, decoder and pricer entry point, plus a tape fuzzer against finite differences.
- A fault-injection runner that plants one bug at a time in a copy of the code, to show each oracle and check can fail.

Only the scalar pricer and tape have measured runs so far: the headline and [RESULTS.md](RESULTS.md) hold all of them. The SIMD lanes, second-order Greeks, the surfaces, the GPU backend and the QuantLib comparison have iteration-only numbers in `docs/NOTES.md`, which are not results; their measured runs come at stage 11. [docs/TASKS.md](docs/TASKS.md) has the plan, [BENCHMARKS.md](BENCHMARKS.md) the published targets with what has been measured against them, and [docs/NOTES.md](docs/NOTES.md) the findings and decisions.

## Build and run

You need CMake 3.25 or later, Ninja, Python 3 and a C++23 compiler. The toolchain comes from the environment (`CC`, `CXX`, and `SDKROOT` on macOS). `clang-format` and `clang-tidy` must be LLVM 23.1.4, and the scripts refuse any other version. Third-party dependencies are pinned archives, fetched into the build tree with their hashes checked. QuantLib is off unless `AAD_PRICER_BUILD_QUANTLIB_COMPARE` is set. The Metal backend, `AAD_PRICER_ENABLE_METAL`, is on for Apple when an Objective-C++ compiler and the Metal framework are found, and off elsewhere. Its tests skip, with the reason, only on a host with no Metal device, and a skipped test still fails `scripts/check.sh` unless it is named.

```sh
cmake --preset release
cmake --build --preset release
ctest --preset release
```

| Preset | Purpose |
|---|---|
| `release` | Optimised, baseline SIMD |
| `debug` | No optimisation |
| `asan-ubsan` | ASan and UBSan |
| `tsan` | TSan |
| `fuzz` | libFuzzer targets with ASan and UBSan |
| `release-gcc` | Optimised, with g++, Linux only |
| `release-avx2` | Optimised, AVX2 with FMA, x86-64 only |
| `release-avx512` | Optimised, AVX-512, x86-64 only. Build only: it has no test preset |

Fetch the data before running the real-file tests. Without it they skip, and `scripts/check.sh` counts a skipped test as a failure.

```sh
scripts/fetch_data.sh            # download the pinned captures and verify their sha256
scripts/fetch_data.sh --verify   # verify what is on disk, with no network
```

Run every check, one after another:

```sh
scripts/check.sh
```

Each step prints one PASS, FAIL or SKIP line and writes a log under `build/logs/check/`. There are 14 steps: the nice level, format, clang-tidy, the repo scan, build and ctest for `release`, `debug`, `asan-ubsan` and `tsan`, a timed run of every fuzz target, the measured oracle plan compared with `references/measured_results.csv`, the README headline and `RESULTS.md` compared with a fresh generation, data verification, actionlint, and fault injection last. The fault-injection step runs against the committed `HEAD`, so uncommitted edits do not reach it. Every step runs even after a failure. `AADP_JOBS` sets the jobs, at most 6 and by default 6, and `AADP_FUZZ_SECONDS` the seconds per fuzz target, by default 60. A skipped test or a step that could not run is a failure unless `--allow-skipped-tests` or `--allow-skip-step` names it. `--only <step,...>` runs part of the list and always exits non-zero, so a partial run can never read as a pass.

Other scripts:

- `scripts/fetch_tools.sh` installs the pinned actionlint into `build/tools/`, checked by sha256. With `--llvm` it also installs LLVM 23.1.4, which is how CI gets its compiler.
- `python3 -I scripts/scan_repo.py` fails if a tracked file holds a home path, an IP address, the current user or host name, an agent notes file, or a raw line of the market data. The exceptions are listed at the top of the script.
- `scripts/verify_commits.sh <range>` builds and tests each commit of a range in an export under `build/commit-check/`. It never checks out a commit.

## Fault injection

A check that cannot fail proves nothing. `scripts/fault_injection.py` plants one bug at a time, from `faults/manifest.json`, and shows that the oracle or check aimed at it fails for the stated reason. There are 357 faults: 62 against the oracles, 267 against the checks and 28 against the fuzz targets. Each is applied to a copy under `build/fault`, never to the working tree. The unmutated copy must pass first, and the mutated run must fail with output matching the fault's reason. Failing for some other reason, such as a compile error where a test failure was expected, counts as not caught.

```sh
python3 -I scripts/fault_injection.py --list                 # print the faults
python3 -I scripts/fault_injection.py --only oracle-philox   # run one fault
python3 -I scripts/fault_injection.py --jobs 6 --output <file>   # run all of them
```

It needs the toolchain in the environment, as the build does. `--kind` runs one kind, and `--source <dir>` mutates an export with no `.git`. The schema and the verdicts are described at the top of the script, and the runner's own tests are in `faults/test_fault_injection.py`. `scripts/check.sh` runs every fault as its last step.

Reports are in `results/<host>/fault-injection-<time>.txt`, with the commit, a scope line and one line per fault. Those committed reports are from Phase 2, when there were 41 faults. On the Mac all 41 were caught. On the Linux host 29 ran and all 29 were caught. The 9 fuzz faults and 3 sanitizer faults were left out there, because sanitizer and fuzz runs stay on the Mac. The latest full `scripts/check.sh` run, at 009605c on the Mac, caught all 355 faults the manifest held then. The two added since, by 67e340e, were run on their own and caught. `docs/NOTES.md` gives each stage's fault results. What the faults found is in `docs/NOTES.md`, under "Fault injection results".

## Results

Results tables come only from `aadp_results_table`, which reads the raw results files, and are never typed by hand:

```sh
build/release/bin/aadp_results_table results/                # print the tables, one per host
build/release/bin/aadp_results_table --docs . --write        # regenerate RESULTS.md and the headline above
build/release/bin/aadp_results_table --docs . --check        # fail if either differs from a fresh generation
```

`--docs` reads `results/headline.csv`, which says which result answers which target and the target's threshold, the target headings in `BENCHMARKS.md`, every file in `results/<host>/`, and the measured oracle runs in `references/`. It holds no number of its own. A row's value comes from the latest run of its workload on its host. No file holds numbers from two hosts, and the tool refuses a file filed under another host's directory. The plain table leaves out a fault-injection report in a host directory, judged by the report's first line; `RESULTS.md` lists those reports in their own table. `results/` holds the stage 3b AAD and bump-and-revalue runs at d1596e0, beside harness self-tests and fault-injection reports.

## Data

The option chain is TAIFEX TXO, European options on the TAIEX, with the matching futures file. Read this before using anything derived from it:

- **These are exchange settlement prices, not tradable quotes.** TAIFEX's rule is that settlement is the last trade, and if there was no trade in the final 15 minutes, TAIFEX decides it. At least 73.7% of all regular-session rows and 52.0% of out-of-the-money rows are exchange-set, and for the 202506 expiry it is 100%. The file has no trade times, so "market-observed" is only an upper bound.
- **It covers one trade date, 2024-11-15.** No stability test is possible.
- **The usable surface reaches only 33 days.** The market-anchored expiries are 5, 12 and 33 days out, so pricing off it is limited to short maturities. Anything longer-dated would be fitted to exchange-set marks and labelled that way.

What remains doubtful, none of it resolved in the data's favour:

1. The licence chain is reasonable, not express: Securities and Futures Bureau, then TAIFEX's authority, then the licence. The listed provider is the Bureau, not TAIFEX.
2. TAIFEX's own terms are ambiguous. Clause 3 exempts data it authorised data.gov.tw to offer, but its next sentence asks for prior written consent to quote or reprint, and the English terms have no exemption at all. The raw file is kept unmodified and the source is cited. This is a reading, not legal advice.
3. Internet Archive's Terms of Use could not be read, because the page is a JavaScript shell. Its developer guide requires a descriptive User-Agent on automated requests, which the fetch script sends. The `id_` URL modifier the pinned links use is observed behaviour, not documented.
4. There is a single point of failure. There is one capture, and if it goes, calibration cannot run until a mirror or a new snapshot is chosen. The fetch script has no fallback source on purpose.
5. The licence covers the open file only. Venue POST quotes were a diagnostic and must not feed calibration.
6. One date only, as above.

The raw files are never committed. `scripts/fetch_data.sh` downloads the Internet Archive captures named in `scripts/data_manifest.txt` and verifies their sha256. `docs/NOTES.md` has the full analysis under "Option chain". Attribution for the data and the third-party build dependencies is in [`NOTICE`](NOTICE).

## CI

`.github/workflows/ci.yml` runs on GitHub. Its first run, at bc3e6d3, failed 9 of 17 jobs: actionlint, clang-tidy, the two GCC jobs, Linux TSan and the four macOS jobs. The fixes for it, and for the later failed runs 41884006533, 41942650525 and 42018873540, are pushed, and CI has confirmed them: run 43309647994, at ae08e87, passed all 22 jobs. `docs/NOTES.md` has the causes. The two release jobs also check that the README headline and `RESULTS.md` match a fresh generation. The workflow covers Linux and macOS, clang and, on Linux, gcc, Debug and Release, ASan with UBSan, TSan, clang-tidy on libc++ and on libstdc++, format, a fuzz smoke, the repo scan, AVX2 and AVX-512 builds, a SIMD lane matrix at 1, 2, 4 and 8 lanes, and the Metal GPU tests on the four macOS jobs, whose runners have a Metal device (`Apple Paravirtual device`). A step prints the device first, and only a runner with none may skip the GPU tests, by name and with a warning. The 8-lane job always runs its tests: natively on a runner with every x86-64-v4 feature, and otherwise under Intel SDE as a Skylake-X (`-skx`), so a green run has tested 8 lanes either way. AVX-512 is build-only on the two measurement hosts, which cannot run it.
